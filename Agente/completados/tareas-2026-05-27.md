## 275A-1 — Fix crítico: pérdida masiva de datos al recargar/borrar tareas

- **Qué:** Investigación profunda de 4 fallos en cascada que causaban borrado total de datos del dashboard. Implementadas 6 soluciones:
  1. **(URGENTE)** Eliminado `default => []` en `getSaveArgs()` de `DashboardApiController.php` — WordPress inyectaba arrays vacíos para campos faltantes, convirtiendo requests parciales en delete-all
  2. **(URGENTE)** Safety guard `esProbableWipeout()` en `useSyncManager.ts` — detecta cuando el cliente va a enviar datos vacíos tras carga exitosa previa, aborta sync
  3. `isDataReady` ahora incluye `habitosInicializado` del store Zustand — evita ventana donde `habitos=[]` pero `isDataReady=true`
  4. WebSocket callbacks cambiados a actualización funcional (`setTareas(prev => ...)`) — elimina race conditions con eventos rápidos
  5. Fix transacción anidada en `BackupsApiController.php` + `DashboardRepository.php` — `$inTransaction` evita START TRANSACTION doble que causaba COMMIT implícito
  6. Sanity check en `TareasRepository`, `HabitosRepository`, `ProyectosRepository` — si `incomingIds=[]` con >5 registros existentes, aborta y retorna false

- **Archivos:**
  - `App/Api/DashboardApiController.php` — Solución 1
  - `App/React/hooks/dashboard/useSyncManager.ts` — Solución 2
  - `App/React/hooks/dashboard/useDashboardSync.ts` — Soluciones 3+4
  - `App/Repository/DashboardRepository.php` — Solución 5
  - `App/Api/BackupsApiController.php` — Solución 5
  - `App/Repository/TareasRepository.php` — Solución 6
  - `App/Repository/HabitosRepository.php` — Solución 6
  - `App/Repository/ProyectosRepository.php` — Solución 6

- **Gotchas:**
  - `replace_string_in_file` falla con oldStrings multi-línea en archivos CRLF — solución: normalizar a LF antes, editar, y Git restaura CRLF al commit
  - `useLocalStorage.setValor` SÍ acepta `(prev => next)` pero la interfaz `UseDashboardSyncProps` tipaba `setTareas` como `(t: Tarea[]) => void` — causaba error TS al usar actualización funcional
  - WordPress REST API inyecta `default` values para campos faltantes — Peligroso cuando `default => []` se combina con `?? []`

- **Sentinel:** No aplica (bug de lógica, no patrón de código)

- **GLORY:** No aplica (lógica específica del proyecto)
