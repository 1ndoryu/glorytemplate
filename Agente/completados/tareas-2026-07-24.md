# Tareas completadas — 2026-07-24

## 247A-1 — Persistir orden manual al arrastrar en modo prioridad

- **Que:** El drag & drop de tareas en el panel de Ejecución funcionaba visualmente, pero el orden manual no persistía. Al re-renderizar (cualquier cambio de estado), `useOrdenarTareas` ejecutaba `compararPorPrioridad()` que reordenaba todo por prioridad, sobreescribiendo el orden que el usuario había establecido con drag.
- **Fix:** Agregar un mecanismo `skipNextSort` en `useOrdenarTareas` que permite saltarse el sort en el render inmediatamente posterior a un drag manual. `reordenarTareas` en `useDashboardCompleto` ahora llama `ordenTareas.skipNextSort()` antes de actualizar el estado, así `useOrdenarTareas` devuelve las tareas sin sortear por un render, y el compararPorPrioridad se reactiva en el siguiente render normal.
- **Archivos modificados:**
  - `App/React/hooks/useOrdenarTareas.ts` — `skipNextSortRef` + `skipNextSort()` + check en `useMemo`
  - `App/React/hooks/useDashboardCompleto.ts` — `reordenarTareasConSkip` wrapper + `dashboardConOrden`
- **Gotchas:** El ref se resetea dentro del propio `useMemo` (durante el render). Esto es seguro porque React renderiza de forma síncrona en este contexto — el ref se lee y se resetea antes de que cualquier otro efecto pueda interferir.
- **Sentinel:** No aplica
- **GLORY:** No aplica (específico del proyecto)

## 247A-2 — Persistir ordenEjecucion de hábitos al recargar página

- **Que:** Al arrastrar hábitos en el panel de Ejecución, el orden (`ordenEjecucion`) se actualizaba en el store local pero NO se persistía al servidor antes de la recarga. El `useSyncManager` actualizaba `lastModified` solo dentro del debounce de 2s — si el usuario recargaba antes, `lastModified <= lastSync` y el sync inicial descargaba datos del servidor (sin el nuevo orden), pisando el cambio local.
- **Fix doble:**
  1. **Primario:** Mover `setSyncMeta({lastModified: Date.now()})` fuera del debounce, justo al detectar `hasChanges`. Ahora `lastModified` se actualiza inmediatamente → al recargar, `lastModified > lastSync` = true → `performInitialSync` sube cambios locales primero.
  2. **Defensivo:** En `setHabitos`, preservar `ordenEjecucion` del estado local existente si el servidor no lo incluye. Actúa como red de seguridad para cualquier caso borde donde el sync no alcance.
- **Archivos modificados:**
  - `App/React/hooks/dashboard/useSyncManager.ts` — `setSyncMeta` inmediato antes del debounce
  - `App/React/stores/habitosStore.ts` — merge defensivo de `ordenEjecucion` en `setHabitos`
- **Gotchas:** El `setSyncMeta` dentro del debounce se mantiene como redundancia segura (Zustand merge). El fix aplica a TODOS los cambios de store, no solo hábitos — cualquier dato que se modifique localmente ahora tiene `lastModified` actualizado inmediatamente.
- **Sentinel:** No aplica
- **GLORY:** No aplica (específico del proyecto)
