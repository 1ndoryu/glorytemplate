## 243A-1 — Fix scraper WhoSampled consumiendo proxy sin reportar resultados
- **Que:** El scraper corría cada hora, hacía requests reales a WhoSampled (consumiendo créditos de proxy residencial), pero reportaba 0 ok / 0 err y nunca activaba auto-stop. Tres problemas encadenados: 1) GestorProcesosFondo lanzaba `scrapy crawl hot_samples` directamente, bypaseando `cron_runner.py` que es quien reporta stats al backend PHP → lotes siempre quedaban en 0/0. 2) `contar_stats_scraper()` hardcodeaba `fallidos=0` → auto-stop nunca progresaba. 3) `evaluarAutoStopScraping()` acumulaba `$nuevo = $acumulado + $fallidos (0)` = sin avance → umbral de 50 imposible de alcanzar.
- **Archivos:** `App/Kamples/Services/GestorProcesosFondo.php`, `App/Kamples/Services/ServicioAutomatizacion.php`, `kamples-scraper/kamples_scraper/spiders/hot_samples.py`, `kamples-scraper/scripts/cron_runner.py`
- **Gotchas:** GestorProcesosFondo usaba `proc_open(['python', '-m', 'scrapy', 'crawl', 'hot_samples'])` que nunca pasaba por cron_runner.py. Ahora usa `['python', 'scripts/cron_runner.py', 'daily']` que reporta stats vía REST al finalizar. Spider ahora escribe telemetría JSON (entries_total/skipped/new) que cron_runner lee para determinar si fue run idle.
- **Sentinel:** No aplica (cambios en Python + PHP backend, no hay regla de Sentinel relevante)
